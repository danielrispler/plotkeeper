# Starting plotkeeper

`plotkeeper` is started by hand in any terminal (danielrispler/plotkeeper#325, spec #319). It replays the event log, writes cards, follows the log as the hook records, and serves the learning layer as a local page, then opens the browser on it. The hook records whether it runs or not; a later start catches up.

## The page and its address

- It listens on 127.0.0.1 only, on port 47800, or the next free port after it.
- Each start has a random token. The browser opens `http://127.0.0.1:<port>/?token=<token>`; the server answers with a cookie (`plotkeeper`, HttpOnly, SameSite=Strict) and sends the browser on to `/`, so the token leaves the address bar. Every other request needs the cookie. A start in a git repository adds `#project=<path>` to the address, its project's main checkout percent-encoded; the fragment never reaches the server and outlives the redirect, and the page opens on that project's map when the saved list holds it, then drops the fragment from the address, so a reload opens on the last viewed project (#756).
- A request whose Host is not `127.0.0.1:<port>` or `localhost:<port>`, or whose Origin, when it has one, is not one of those, is refused with 403, as is a request with no cookie or a wrong token.
- The page is the built `dist/`, embedded in the program when it is built (a build without `dist/` serves nothing).
- The map is the page's main content, under a heading read only by assistive tech. The page's first Tab shows a "Skip to the map" link at the top bar's start; Enter on it moves focus past the session list into the map (#461).

## Commands and events

- A command is `POST /api/<command>` with its arguments as JSON, in the camel case the page writes. The reply is the command's JSON reply. A refused command answers 500 with its reason as a JSON string, a missing or mistyped argument 400, a command the page does not have 404. The commands are the learning-layer and session-view ones, answered by the function of the same name in the `server` crate; terminals, projects, branches, skills and usage are not served.
- `GET /events` is one server-sent event stream: `event: <name>` and `data: <json>`, the events the window used to receive (`sessions`, `cards`, `selected`, `notice`, `writer-notice`, `map-landed`, and the rest), and a comment every 15 seconds.
- The page tells the server whether its tab is visible and focused (`page_focus`); the read loop treats that as the window's focus. With no tab listening, nothing is focused.
- `POST /api/log` puts the page's log line in plotkeeper's log (stderr).
- `settings-files` carries the text of `settings.json` and `keymap.json`, as the `settings_files` command answers it. The read loop sends it when either file's text differs from what it last sent (#550), so a hand edit reaches every open page ([settings](../settings.md)).
- `server-error` carries the message of an error plotkeeper logged, which is also on stderr (#550). The page shows it in the notice line until it is dismissed. Warnings stay on stderr only, the HTTP client's lines are never logged, and a page's own log lines are not sent back, since the page that logged an error already shows it. An error logged while no page is open is on stderr only.
- A failed `writer_notice` or `wired` at the page's start is a warning in the log, not shown.

## One plotkeeper per data folder

The first start holds a lock on `plotkeeper.lock` in the data folder and writes its port, token and version to `plotkeeper.running.json` there (mode 0600). A second start finds the lock held, opens the browser on the first one's address and exits. Started in a git repository, it first sends its folder to the first one's `register_folder` command, with the token from the running file as the page's cookie, so the first one adds its project to the saved list and sends the page the new list; the address it opens names that project. A failed call is said on stderr and the page opens anyway, on the last viewed project (#756, [sessions](sessions.md)). When the first one's version differs from its own, it first prints "plotkeeper <old> is still running; stop it (Ctrl+C) and run again to use <new>" (#439); it never stops the first one, whose background runs go on. A running file from before #439, with no version, opens the page with no notice. After it takes the lock and refreshes the hook copies, the first start asks in the terminal before it wires the harnesses it finds with no answer yet, and serves whatever the answer; with no terminal it asks nothing, wires nothing and prints `plotkeeper install --yes` (#434, [plugin.md](../plugin.md)). Its summary, question and wiring lines go to stderr, so stdout's first line is the page's address. A second start while the first is still starting, or waiting on its question, finds no address within 2 seconds and exits saying so. A second start never asks. While no harness is wired, because the user declined or the start had no terminal, the Map view's head, which shows with or without a session open, says "Not recording: no agent is wired. Run `plotkeeper install` in a terminal to wire them." (#437). The page asks the server (`wired`, read afresh from install's record each time) when it opens and at each focus, so the line goes once `plotkeeper install` wires a harness, with no restart of the page or the server; it has no Dismiss. Ctrl+C (or SIGTERM) stops the server, removes that file and frees the lock; the stores write by temp file and rename, so a stop never leaves one half written.

At start it applies the writer `settings.json` names (`summaries.writer`, `claude` by default), so summaries are written with it before any page opens. A start asks `gh` about the PRs of the sessions' repositories once and writes the PR briefs of at most 3 ready PRs whose head moved within the catch-up window (`briefBackfill.hours`, 2 by default; the older `catchUp.hours` is still read), the newest first, always with `claude -p`; any other ready PR is written when its brief is opened (see [PR briefs](pr-briefs.md)). The writer's failures reach the page as `writer-notice`; see [cards](cards.md).

`PLOTKEEPER_NO_BROWSER=1` leaves the browser closed; the address is printed either way (`plotkeeper: <url>`).

## A panic stops plotkeeper

A panic on any thread (the read loop, a request, a background run's thread, a turn's writing job) stops plotkeeper (#551, spec #548). It prints one error line to stderr, `thread '<name>' panicked at <file>:<line>:<column>: <message>; plotkeeper stops`, and exits with code 101; the operating system frees the lock on `plotkeeper.lock`. It never goes on half-working, with a poisoned lock that fails every later command or a served page whose read loop is gone. Starting it again is safe: the sessions are rebuilt from the event log, the stores write by temp file and rename, and the background runs a start before left are picked up. The hooks are processes of their own and are not stopped by it.

## What's new after an update

At start the page asks the server for plotkeeper's package version (`about`, #527). The page keeps the last version it showed in `localStorage` (`shown-version`). With none stored, a first install, it stores the current one and shows nothing; with the same version it shows nothing, so a rebuild without a version change stays quiet. With an older one, a downgrade, it stores the current one and shows nothing. With a newer one (X.Y.Z compared as numbers) it shows one toast, "Updated to X.Y.Z" with a "What's new" link to that version's GitHub Release (`https://github.com/danielrispler/plotkeeper/releases/tag/vX.Y.Z`) and a ×, in the toasts' region under the copy toast, not in colour. It stays until its ×. The new version is stored only once the toast has shown while the tab was visible: a page reloaded in a hidden tab stores it at the tab's first visible moment. The changelog's text stays on GitHub; a version published without a Release links to a missing page. A browser that refuses `localStorage` shows nothing and fails nothing.

## Seen and notices

Seen and notices are the page's (danielrispler/plotkeeper#331); the Dock badge, the macOS notifications and the sounds are gone.

- A card counts as seen only when its tab is visible (Page Visibility) and focused (`document.hasFocus()`), the card has been in view for half a second, and Daniel interacted with it (his pointer moved over it, he pressed on it, scrolled over it or focused it). A browser on a second screen shows cards but never marks them seen while he works in his IDE.
- When a notice is due and no tab is visible and focused, the server sends a `notification` event and the page raises a browser notification (one tag, so tabs do not stack them). A focused tab shows the notice in the page instead. The page asks for the notification permission once, at Daniel's first press.
- The tab's title carries the number of unseen sessions, as the bar's unseen chip counts them: `(3) plotkeeper`, plain `plotkeeper` with none.
