# Development

## The crates

- `plugin-agy/`: the studio's plugin for agy (#43). `hooks.json` runs `studio-hook` for agy's six events through an inline wrapper that always exits 0 with empty stdout; `studio-hook` writes an agy event only when `STUDIO_TERMINAL_ID` is set. `agy plugin install` copies the folder, so the app renders it with `studio-hook`'s path, compares it with `~/.gemini/config/plugins/studio/` at start and offers "Install it" when it is missing or stale.
- `plugin/`: the Claude Code plugin. On thirteen hook events, `SubagentStart` and `SubagentStop` among them, it runs `studio-hook`. On the `PreToolUse` of `AskUserQuestion` and `ExitPlanMode`, on every `PermissionRequest`, and on the `PermissionDenied` and `PreToolUse` of Bash, it also runs `studio-answer`, synchronously.
- `hook/`: `studio-hook`, which appends each hook payload as one line to the event log, and the log's path; it also records each turn's and worker's trees and the worktree roots a call touched (`studio_touched_roots`), from the folders and paths the call names, the roots `git worktree list` gives and the roots it already knows; and `studio-answer`, the answer hook (danielrispler/Falinks#477, danielrispler/Falinks#478): while the studio watches the asking session, it waits up to 120 seconds for an answer from the card and returns it: a question's `answers`, a plan's approval or rejection, a permission's allow or deny. It logs that answer as a `StudioAnswer` line, which clears "needs you" for a plan or a permission at once. Otherwise it returns at once with no decision and the terminal asks. On a Bash `PermissionDenied` it leaves a request in `blocked/<session>/` and waits up to 600 seconds, while the window shows life whatever session it shows, for Allow (`retry: true`) or Decline; Allow also leaves a 30-minute one-time pass in `passes/<session>/`, which the retry's `PreToolUse` claims and its `PermissionRequest` spends.
  - Its files and trust boundary are in `hook/src/answer.rs`.
- `core/`: the studio core, plain Rust whose only I/O is reading the sessions' transcripts (`src/transcript.rs`, `.jsonl` files only), and `scrub`, which turns event log lines into test fixtures. At start the app takes the state its last start saved, `studio-state.json` beside the log, and replays only the log from where that state stopped, then feeds it each new line live; a pruned log, a state of another format or one that does not read means a replay from the start. It keeps the step ledger (`ledger`), the checks (`checks`: the statement parser, a run's worktree and exit code, running and background runs, the feed's checks, and the typical durations with the 2-minute rule: their recording, median and lookup, which `lib.rs` calls), each turn's files (`turn_files`) and the facts Ask shows (`ask`).
  - Only live lines request cards and notifications.
- `understanding/`: the understanding layer's I/O: the card writer interface (cards, turn summaries, Quizzes, goals and "Design so far"), the `claude -p` writer and a fake, the worktree fingerprint, the card store with the briefs, the turn summaries, Turn writing (`turn_writing.rs`: what a turn's end, a long check's start and a worker's return write, on a queue for each session), the offer table and its record (`offer.rs`, `offers.jsonl` beside the event log), the retests and the self-test's report (`self_test`), Claude Code's version kept beside the event log, and `weekly`, the command that prints the week's thinking and surprise rates, ratings by level and reason and flags on the key, then the drift: unrecognised wake-ups and version changes.
- `terminal-daemon/`: `studio-terminal-daemon`, the background process that owns the terminals, so they outlive the app (danielrispler/Falinks#322, danielrispler/Falinks#464). Its own crate and binary; the app links only its client library and runs the binary, so an app rebuild neither rebuilds nor restarts it. `serve` runs it on `~/Library/Application Support/dev.falinks.studio/terminal-daemon.sock`, one at a time; the protocol is in `src/lib.rs`.
  - Every terminal starts through `$SHELL -l`, so the profile sets `PATH` even when the studio was started from the Dock, and without `CLAUDE*` or terminal-identity variables. That shell is not interactive, so zsh reads `~/.zprofile` and `~/.zshenv` but not `~/.zshrc`. Set up every tool a session needs, such as `node` and `npm`, in one of the first two; nvm's installer writes its lines to `~/.zshrc`, so move them to `~/.zprofile` (#20). `attach <terminal>` connects any terminal app to one of its terminals; Ctrl-] detaches.
- `workbench/`: workbench git (danielrispler/Falinks#328, module 7): the picker's workspaces from `git worktree list --porcelain`, and the `claude` command a session's terminal runs.
- `src-tauri/`: the app's Rust shell, with the terminal daemon's client (`src/terminal.rs`). `ui/`: its TypeScript pane.

It leaves out the shell, which needs `dist/` from `npm run build`.

Each crate's integration tests are one test binary, `it`: its `Cargo.toml` sets `autotests = false`, and `tests/main.rs` declares each `tests/*.rs` file as a module, so a new test file needs a `mod` line there. Helpers the files share live in `tests/common.rs`; the git helpers that `hook`, `understanding` and `workbench` share (an isolated `git`, a one-commit repository, a bare `origin`) live in the `studio-test-support` crate (`test-support/`), a dev-dependency that depends on no workspace crate. The fake writers of `understanding/tests` are `Scripted` in its `common.rs`. In `ui/tests/`, `dom.mjs` holds the fake document (`fakeDocument`) and the `invoke` stub (`tauri`).

`npm test` (after `npm ci`) builds the UI with `tsc` and runs `terminal-daemon/tests/replay.test.mjs`: a terminal's bytes replayed into a headless xterm of another size, with the resize sent, match a fresh render at that size; and `ui/tests/`: the UI's pure functions on the `tsc` output in `dist/`, such as the width rule's layout, the terminal's key mapping (`keys`) and its file paths (`paths`), a check card's verdict and quiz state (`check_cards`), what "now" holds in each state and a folded turn's line (`rail`), the evidence line (`evidence`), a Quiz before and after a pick or "Show the rest anyway" (`quiz`), the banner's 14 and 15 minutes (`banner`), the top bar's survival order (`layout`), hover as a state machine on an injected clock (`hover`), and Ask and the diff pane (`ask`, `diff`), the agent logos and the rows that show them (`logos`), the text each layout cut holds in a title (`full-text`), Pull main's flow and its errors (`pull`), the usage glance and tiles (`usage`), the note toast, the context warning's crossings and the unseen chip (`notes`), a folded turn's unseen card as one title row that opens in place (`unseen-card`), when a card counts as shown and when its opened row goes (`card-shown`), a worker's card in the turn its wake-up opened (`worker-card`), the settings page's rows, steps and the value each control writes (`settings-page`), the snap page and its fixtures (`snap`: the stub, the rail's and the recorded terminal's), and the README's limits and links (`readme`); opening a thing in place leaves every other node of the rail the same object, on the tests' small DOM (`dom.mjs`).

The window calls the shell only through `invoke` (`ui/dom.ts`), which takes a command of the `Commands` map in `ui/types.ts` and gives its reply that command's type. The snap fixtures (`scripts/snap/fixtures.ts`, `rail-fixtures.ts`) are typed against the map, and `scripts/snap/base.ts` answers every command whose reply the window reads, so `npm run build` (`tsc -p scripts/snap`) fails on a reply that lacks a field, and on a command `base.ts` does not answer. A fixture may leave a command out: each starts from `...base`.

The Rust half of that map is checked by the wire tests (#246), with no code generator: `core/tests/wire.rs`, `understanding/tests/wire.rs` and `workbench/tests/wire.rs` serialize real values of the types the shell sends (sessions replayed from the fixtures, the session list's rows, the selection, checks, a subagent's log, a session's cards with its brief and Open items, a turn's summary, Home's learning items, Ask's facts, a hunk, a check's output, the workspaces, git state, branches, losses and plan usage) as the shell does, and write them as `const` literals, each typed with its mirror in `ui/`, into `scripts/wire/<crate>.ts` (`scripts/wire/samples.rs`). `tsc -p scripts/wire` then checks them: a typed object literal fails on a field its type does not have, so a field renamed or added in Rust, or a saved-only field (`skip_serializing_if = "crate::saved::unsaved"`) that reaches the wire, fails `npm run check`, as does a required field the wire lacks. A field the shell sends that the window never reads is optional in `ui/types.ts`, so the snap fixtures may leave it out; its removal from the wire passes, its rename does not. Each crate's test writes only its own file, so run the three before `tsc -p scripts/wire` by hand, or it checks an older run's samples. The limit: the check sees only the shapes its samples produce, so an optional field no sample fills, or an enum value none holds, is not checked.

`npm run snap:rail -- <folder>` renders the rail's states from fixtures in Chrome, which `npm run check` leaves out. `npm run snap:all` renders every fixture once, one per core at a time, and fails if one ends in `snap:fail` or an uncaught error in the page, and when Chrome itself exits non-zero it prints Chrome's exit status and the tail of its stderr first; CI runs it in a job of its own, beside `npm run check`. `npm run snap:readme` draws the README's four pictures into `docs/studio/assets/readme/` the same way. `scripts/snap/record-terminal.sh` records the terminal for the hero picture; it runs a nested `claude` on your subscription, so run it yourself, outside auto mode.

`node scripts/review/outside-review.mjs [--force] [--model <id>] [--since <sha>] [--out <folder>]` is the outside review (#279): Gemini, through `agy`, reads a risky diff before its PR is opened (`AGENTS.md`, "Finish with a PR"). It reads HEAD's commits since the merge-base with `origin/main`, and only when the diff changes a struct or enum that derives `Deserialize` outside a `tests/` folder (judged from the whole type in the file after the change, not from the changed lines), a hunk of code that names one of the card store's files, or the turn-writing job queue (`understanding/src/turn_writing.rs`), or when the branch's issue has sub-issues, a spec. `--force` reviews any diff, and `--since <sha>` reviews that commit and those after it, for round 2. Any other diff prints `skipped: no risk match`. The review is one `agy -p` run with `gemini-4-neon-medium`, in a throwaway folder that holds a detached worktree of HEAD, the diff and the file lists. `scripts/review/deny-hook.mjs` denies it every tool but a read inside that folder (#283) and `finish`, through which `agy --json-schema` hands over its answer, and `STUDIO_TERMINAL_ID` is removed, so Studio shows no session for it. Afterwards the script checks that the throwaway tree is clean, says so if it is not, and removes it; killed mid-review, it ends `agy` and removes the tree first. It prints `reviewed: <n> findings`, then the findings' JSON file (in `--out`, else the system's temp folder), the minutes, the tokens and the Gemini quota left before and after. Whatever stops it (no `agy`, the 15-minute cut, a used-up quota) prints `review unavailable: <reason>` and exits 0; only a wrong option exits 2, before any review. `ui/tests/outside-review.test.mjs` tests the decision, the `agy` call, the verdicts and the hook, and runs the script in a scratch repository with a stand-in `agy`; the real `agy` run was checked by hand (`local-evidence/2026-11-22-outside-review/`).

`npm run check` runs them all in order: `cargo fmt --all --check`, `npm run build`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo nextest run --locked --workspace` (the shell included), `tsc -p scripts/wire` on the samples the wire tests just wrote, and `npm run test:node`. nextest runs the same tests as `cargo test`, but runs every test in a process of its own, all binaries' at once; install it with `brew install cargo-nextest`. CI runs `npm ci` and `npm run check` in one job, and `npm run build` and `npm run snap:all` in another, in `.github/workflows/studio.yml`, on macOS. It runs for each push to `main` or to an `issue-*` branch, and for each pull request from any other branch. The engine's `checks.yml` and `ci-checks` skip the studio.

## The live run

The tests above run on events written by hand. `core/tests/run-unisolated-worker.sh` proves that Claude Code's real events have the shape they assume (#214): a scripted session in a temporary repository, with this checkout's plugin, spawns a background subagent that is not isolated, which makes a worktree with `git worktree add`, writes a 42-line file in it through Bash from the session's folder and commits. The script passes when the subagent's events carry the worktree in `studio_touched_roots` with a start and an end tree whose diff holds the file, and when `offers.jsonl` gained a line for that worker with a card offered; it prints pass or fail for each with the line that decided it.

Run it with Studio open on the build under test, since the app writes the offers record; with Studio closed, or on an older build, the offers check fails. It adds one throwaway session to your list, copies nothing into the repository and removes its temporary repository and worktree. It runs a nested `claude` on your subscription, so run it yourself, outside auto mode:

    core/tests/run-unisolated-worker.sh | tee run.txt

## Recorded logs

Three fixtures in `core/tests/fixtures/` are real event logs, scrubbed by `scrub` (`core/src/bin/scrub.rs`). Each event keeps its shape and loses its content: text becomes `…`, and lists and objects become empty, except for what stays. What stays: ids, event names, `cwd`, the permission mode, a session's start source and end reason, agent ids and types, the `description` of a spawn or a Bash command, `isolation`, the paths of the files a tool reads or writes, skill names, the types and statuses in tool results, background tasks without their commands, exit codes, numbers, flags and timings.

An MCP tool keeps no text. Transcript and output paths become `…`. A prompt keeps only the markup Claude Code adds, with its ids and statuses, so a wake-up stays one; any other tag becomes `<…>`. A last message that asks Daniel something becomes `…?`.

- `checkpoint-day.jsonl`: the events of 2026-10-30, the checkpoint day of danielrispler/Falinks#347. Some of its sessions were still open at midnight.
- `subagent-run.jsonl`: a scripted session in a temporary repository that spawns a worktree worker and a read-only helper in the background, then stops the helper.

- `blocked-run.jsonl`: an interactive session in auto mode, in a temporary repository, whose foreground and background nested `claude -p` are blocked, allowed by a fake studio, retried and run, with the background one's wake-up. A command stays only when it carries the marker `studio-fixture-`; a wake-up's summary keeps its status and exit code and loses its quoted description. `core/tests/blocked_commands.rs` replays it.

Re-record the second when Claude Code's version changes. The script runs a nested `claude` on your subscription, so run it yourself, outside auto mode:

    core/tests/record-subagent-run.sh

Quit the studio app first: it would take the session as live and ask for cards. The script builds `studio-hook`, runs the session with this checkout's plugin, and scrubs the session's events from the event log into the fixture. Before you commit the new fixture, run `cargo test` and check that each text it keeps is a label, an id or a path.

Re-record the third the same way, with Claude Code's version, or when the blocked-command hooks change: quit the studio app, then run `core/tests/record-blocked-run.sh` straight in a terminal, with its output not redirected, since the session is interactive (an `ask` has no prompt to go to under `claude -p`). Watch the agent, and type `/exit` after its last reply, once the background command's wake-up has come. Ctrl-C is ignored by the script but ends `claude` early. The script plays the studio (heartbeat, one-time pass and Allow answer) and gives the session an `autoMode.hard_deny` rule through `--settings` so auto mode blocks its marked commands. It writes the fixture only when the log holds a `PermissionDenied`, a `StudioAnswer` and a wake-up for the session, and names what is missing otherwise.

The app tells you when the version changed. At a session's first `Stop`, it reads Claude Code's version from the session's transcript, the `.jsonl` file at the event's `transcript_path`, and opens no other file. It keeps each new version, with when it was first seen, in `claude-versions.txt` beside the event log. A version that differs from the last one kept shows a one-line notice at the top of the pane, a line in the Studio log, and a line in `weekly`. The first version kept has nothing to compare with, so it shows nothing.
