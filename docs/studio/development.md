# Development

## The crates

- `plugin-agy/`: the studio's plugin for agy (#43). `hooks.json` runs `plotkeeper-hook` for agy's six events through an inline wrapper that always exits 0 with empty stdout; `plotkeeper-hook` writes an agy event from any terminal, and drops every event from a process with `PLOTKEEPER_INTERNAL=1` (#323). `plotkeeper install` renders it with the path of `plotkeeper-hook` in the data folder's `bin/` and installs it with `agy plugin install`, which copies the folder ([install](plugin.md)).
- `plugin/`: the Claude Code plugin, which `plotkeeper install` renders with the data folder's `bin/` and installs with `claude plugin install` ([install](plugin.md)). On thirteen hook events, `SubagentStart` and `SubagentStop` among them, it runs `plotkeeper-hook`. On the `PreToolUse` of `AskUserQuestion` and `ExitPlanMode`, on every `PermissionRequest`, and on the `PermissionDenied` and `PreToolUse` of Bash, it also runs `plotkeeper-answer`, synchronously.
- `hook/`: `plotkeeper-hook`, which appends each hook payload as one line to the event log, and the log's path; it also records each turn's and worker's trees and the worktree roots a call touched (`studio_touched_roots`), from the folders and paths the call names, the roots `git worktree list` gives and the roots it already knows; and `plotkeeper-answer`, the answer hook (danielrispler/Falinks#477, danielrispler/Falinks#478): while the studio watches the asking session, it waits up to 120 seconds for an answer from the card and returns it: a question's `answers`, a plan's approval or rejection, a permission's allow or deny. It logs that answer as a `StudioAnswer` line, which clears "needs you" for a plan or a permission at once. Otherwise it returns at once with no decision and the terminal asks. On a Bash `PermissionDenied` it leaves a request in `blocked/<session>/` and waits up to 600 seconds, while the window shows life whatever session it shows, for Allow (`retry: true`) or Decline; Allow also leaves a 30-minute one-time pass in `passes/<session>/`, which the retry's `PreToolUse` claims and its `PermissionRequest` spends.
  - Its files and trust boundary are in `hook/src/answer.rs`.
- `core/`: the studio core, plain Rust whose only I/O is reading the sessions' transcripts (`src/transcript.rs`, `.jsonl` files only), and `scrub`, which turns event log lines into test fixtures. At start the app takes the state its last start saved, `studio-state.json` beside the log, and replays only the log from where that state stopped, then feeds it each new line live; a pruned log, a state of another format or one that does not read means a replay from the start. It keeps the step ledger (`ledger`), the checks (`checks`: the statement parser, a run's worktree and exit code, running and background runs, the feed's checks, and the typical durations with the 2-minute rule: their recording, median and lookup, which `lib.rs` calls), each turn's files (`turn_files`) and the facts Ask shows (`ask`).
  - Only live lines request cards and notifications.
- `understanding/`: the understanding layer's I/O: the writer interface (turn summaries, goals, "Design so far", Ask, names and risk notes), the `claude -p` writer and a fake, the worktree fingerprint, the card store with the briefs, the turn summaries, Turn writing (`turn_writing.rs`: what a turn's end and a worker's return write, on a queue for each session), which files are logic and which are tests (`logic_file.rs`), Claude Code's version kept beside the event log, and `weekly`, the command that prints the drift: unrecognised wake-ups and version changes.
- `workbench/`: workbench git (danielrispler/Falinks#328, module 7): the picker's workspaces from `git worktree list --porcelain`, and the `claude` command a session's terminal runs.
- `system-map/`: `studio-system-map`, a library and the `system-map` binary that check `system-map.json` against the repository and say which parts a change touches (`docs/studio/behaviour/map.md`). `npm run check` runs `system-map check` after the tests.
- `server/`: `studio-server`, the state and the logic behind the page's commands, and the `plotkeeper` program that serves it (`src/bin/plotkeeper.rs`, the local page in `src/web.rs`, one function for each command in `src/api.rs`). Its modules include the read loop (`read_loop.rs`), the Map view's (spec #306: `map.rs` the payload, Daniel's positions and tiers and the guarded `git fetch`; `fog.rs` the commits since Daniel last caught up, kept per part, and what reading a brief clears; `history.rs` a part's history, the map at a past commit, a commit's files and a PR's; `ci_laws.rs` the default branch's last finished CI run, the law tests that failed in it and the words for a failed check; `stop_rules.rs` the usage log and the one-time review's counts) and the PR briefs' (spec #334: `prs.rs` which PRs are ready, `pr_briefs.rs` writing, keeping and rewriting the briefs, `ratify.rs` what Daniel accepted or overturned) and `settings.rs`. `ui/`: its TypeScript page.
- `src-tauri/` and `terminal-daemon/`: the archived Tauri desktop app and the daemon that owned its terminals, out of the workspace, CI and `npm run check`, unmaintained and kept as they were (danielrispler/plotkeeper#334, #332; each folder's `README.md`).

Each crate's integration tests are one test binary, `it`: its `Cargo.toml` sets `autotests = false`, and `tests/main.rs` declares each `tests/*.rs` file as a module, so a new test file needs a `mod` line there. Helpers the files share live in `tests/common.rs`; the git helpers that `hook`, `understanding` and `workbench` share (an isolated `git`, a one-commit repository, a bare `origin`) live in the `studio-test-support` crate (`test-support/`), a dev-dependency that depends on no workspace crate. The fake writers of `understanding/tests` are `Scripted` in its `common.rs`. In `ui/tests/`, `dom.mjs` holds the fake document (`fakeDocument`) and the `invoke` stub (`tauri`).

`npm test` (after `npm ci`) builds the UI with `tsc` and runs `ui/tests/`: the UI's pure functions on the `tsc` output in `dist/`, such as the width rule's layout, the terminal's key mapping (`keys`) and its file paths (`paths`), what "now" holds in each state and a folded turn's line (`rail`), the evidence line (`evidence`), the banner's 14 and 15 minutes (`banner`), the top bar's survival order (`layout`), hover as a state machine on an injected clock (`hover`), and Ask and the diff pane (`ask`, `diff`), the agent logos and the rows that show them (`logos`), the text each layout cut holds in a title (`full-text`), Pull main's flow and its errors (`pull`), the usage glance and tiles (`usage`), the note toast, the context warning's crossings and the unseen chip (`notes`), the PR brief's logic (`map-brief`: a story's and a chapter's playlist, the player that reopens where it left off, the reading gate on the last story step, the checks, the story steps without the Ratify one), the tray's rows (`map-tray`), the rail's row of a brief waiting (`rail-brief`) and the accept and overturn rows (`ratify`), the retired cards and Quiz staying gone (`cards-retired`, `quiz-retired`), the settings page's rows, steps and the value each control writes (`settings-page`), the snap page and its fixtures (`snap`: the stub, the rail's and the recorded terminal's), and the README's limits and links (`readme`), and the Map view's logic: the map file, placement, drag, links and the layered Esc, and which scrub is the newest (`map`), live agents on the parts and the not-placed list (`map-agents`), broken laws and the proof drawer (`map-drawer`), when an element counts as seen (`seen`), and the stop rules' review (`stop-rules`); opening a thing in place leaves every other node of the rail the same object, on the tests' small DOM (`dom.mjs`).

The window calls the shell only through `invoke` (`ui/dom.ts`), which takes a command of the `Commands` map in `ui/types.ts` and gives its reply that command's type. The snap fixtures (`scripts/snap/fixtures.ts`, `rail-fixtures.ts`) are typed against the map, and `scripts/snap/base.ts` answers every command whose reply the window reads, so `npm run build` (`tsc -p scripts/snap`) fails on a reply that lacks a field, and on a command `base.ts` does not answer. A fixture may leave a command out: each starts from `...base`.

The Rust half of that map is checked by the wire tests (#246), with no code generator: `core/tests/wire.rs`, `understanding/tests/wire.rs` and `server/tests/wire.rs` serialize real values of the types the shell sends (sessions replayed from the fixtures, the session list's rows, the selection, checks, a subagent's log, a session's cards with its brief and Open items, a turn's summary, Home's learning items, Ask's facts, a hunk, a check's output, the workspaces, git state, branches, losses and plan usage, and the Map view's `MapState` and the `UserState` its commands return, #333) as the shell does, and write them as `const` literals, each typed with its mirror in `ui/`, into `scripts/wire/<crate>.ts` (`scripts/wire/samples.rs`). `tsc -p scripts/wire` then checks them: a typed object literal fails on a field its type does not have, so a field renamed or added in Rust, or a saved-only field (`skip_serializing_if = "crate::saved::unsaved"`) that reaches the wire, fails `npm run check`, as does a required field the wire lacks. A field the shell sends that the window never reads is optional in `ui/types.ts`, so the snap fixtures may leave it out; its removal from the wire passes, its rename does not. Each crate's test writes only its own file, and the files are gitignored, so a file whose test was deleted stays behind and fails `tsc` against a newer `ui/`. `npm run check` deletes `scripts/wire/*.ts` before the tests; by hand, do the same and run the wire tests before `tsc -p scripts/wire`, or it checks an older run's samples. The limit: the check sees only the shapes its samples produce, so an optional field no sample fills, or an enum value none holds, is not checked.

`npm run snap:rail -- <folder>` renders the rail's states from fixtures in Chrome, which `npm run check` leaves out. `npm run snap:all` renders every fixture once, one per core at a time, and fails if one ends in `snap:fail` or an uncaught error in the page, and when Chrome itself exits non-zero it prints Chrome's exit status and the tail of its stderr first; CI runs it in a job of its own, beside `npm run check`. `npm run snap:readme` draws the README's three pictures into `docs/studio/assets/readme/` the same way.

`node scripts/review/outside-review.mjs [--force] [--model <id>] [--since <sha>] [--out <folder>]` is the outside review (#279): Gemini, through `agy`, reads a risky diff before its PR is opened (`AGENTS.md`, "Finish with a PR"). It reads HEAD's commits since the merge-base with `origin/main`, and only when the diff changes a struct or enum that derives `Deserialize` outside a `tests/` folder (judged from the whole type in the file after the change, not from the changed lines), a hunk of code that names one of the card store's files, or the turn-writing job queue (`understanding/src/turn_writing.rs`), or when the branch's issue has sub-issues, a spec. `--force` reviews any diff, and `--since <sha>` reviews that commit and those after it, for round 2. Any other diff prints `skipped: no risk match`. The review is one `agy -p` run with `gemini-4-neon-medium`, in a throwaway folder that holds a detached worktree of HEAD, the diff and the file lists. `scripts/review/deny-hook.mjs` denies it every tool but a read inside that folder (#283) and `finish`, through which `agy --json-schema` hands over its answer, and `PLOTKEEPER_TERMINAL_ID` is removed, so Studio shows no session for it. Afterwards the script checks that the throwaway tree is clean, says so if it is not, and removes it; killed mid-review, it ends `agy` and removes the tree first. It prints `reviewed: <n> findings`, then the findings' JSON file (in `--out`, else the system's temp folder), the minutes, the tokens and the Gemini quota left before and after. Whatever stops it (no `agy`, the 15-minute cut, a used-up quota) prints `review unavailable: <reason>` and exits 0; only a wrong option exits 2, before any review. Every run, whatever its verdict, also appends one line to `local-evidence/outside-review/runs.jsonl` in the main checkout (the time, branch, head, base, verdict, why it ran, model, round, findings, tokens, seconds and the quota before and after), and a reviewed run's findings file is kept beside it (#302); it records only where git ignores `local-evidence/`, and a record that cannot be written changes nothing else. `ui/tests/outside-review.test.mjs` tests the decision, the `agy` call, the verdicts and the hook, and runs the script in a scratch repository with a stand-in `agy`; the real `agy` run was checked by hand (`local-evidence/2026-11-22-outside-review/`).

`npm run check` runs them all in order: `cargo fmt --all --check`, `npm run build`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `rm -f scripts/wire/*.ts`, `cargo nextest run --locked --workspace` (the shell included), the map check (`cargo run --locked -q -p studio-system-map -- check`), `tsc -p scripts/wire` on the samples the wire tests just wrote, and `npm run test:node`. nextest runs the same tests as `cargo test`, but runs every test in a process of its own, all binaries' at once; install it with `brew install cargo-nextest`. CI runs `npm ci` and `npm run check` in one job, and `npm run build` and `npm run snap:all` in another, in `.github/workflows/studio.yml`, on macOS. It runs for each push to `main` or to an `issue-*` branch, and for each pull request from any other branch. The engine's `checks.yml` and `ci-checks` skip the studio.

## The live run

The tests above run on events written by hand. `core/tests/run-unisolated-worker.sh` proves that Claude Code's real events have the shape they assume (#214): a scripted session in a temporary repository, with this checkout's plugin, spawns a background subagent that is not isolated, which makes a worktree with `git worktree add`, writes a 42-line file in it through Bash from the session's folder and commits. The script passes when the subagent's events carry the worktree in `studio_touched_roots` with a start and an end tree whose diff holds the file; it prints pass or fail with the line that decided it.

It adds one throwaway session to your list, copies nothing into the repository and removes its temporary repository and worktree. It runs a nested `claude` on your subscription, so run it yourself, outside auto mode:

    core/tests/run-unisolated-worker.sh | tee run.txt

## Recorded logs

Three fixtures in `core/tests/fixtures/` are real event logs, scrubbed by `scrub` (`core/src/bin/scrub.rs`). Each event keeps its shape and loses its content: text becomes `…`, and lists and objects become empty, except for what stays. What stays: ids, event names, `cwd`, the permission mode, a session's start source and end reason, agent ids and types, the `description` of a spawn or a Bash command, `isolation`, the paths of the files a tool reads or writes, skill names, the types and statuses in tool results, background tasks without their commands, exit codes, numbers, flags and timings.

An MCP tool keeps no text. Transcript and output paths become `…`. A prompt keeps only the markup Claude Code adds, with its ids and statuses, so a wake-up stays one; any other tag becomes `<…>`. A last message that asks Daniel something becomes `…?`.

- `checkpoint-day.jsonl`: the events of 2026-10-30, the checkpoint day of danielrispler/Falinks#347. Some of its sessions were still open at midnight.
- `subagent-run.jsonl`: a scripted session in a temporary repository that spawns a worktree worker and a read-only helper in the background, then stops the helper.

- `blocked-run.jsonl`: an interactive session in auto mode, in a temporary repository, whose foreground and background nested `claude -p` are blocked, allowed by a fake studio, retried and run, with the background one's wake-up. A command stays only when it carries the marker `studio-fixture-`; a wake-up's summary keeps its status and exit code and loses its quoted description. `core/tests/blocked_commands.rs` replays it.

Re-record the second when Claude Code's version changes. The script runs a nested `claude` on your subscription, so run it yourself, outside auto mode:

    core/tests/record-subagent-run.sh

Quit the studio app first: it would take the session as live and ask for cards. The script builds `plotkeeper-hook`, runs the session with this checkout's plugin, and scrubs the session's events from the event log into the fixture. Before you commit the new fixture, run `cargo test` and check that each text it keeps is a label, an id or a path.

Re-record the third the same way, with Claude Code's version, or when the blocked-command hooks change: quit the studio app, then run `core/tests/record-blocked-run.sh` straight in a terminal, with its output not redirected, since the session is interactive (an `ask` has no prompt to go to under `claude -p`). Watch the agent, and type `/exit` after its last reply, once the background command's wake-up has come. Ctrl-C is ignored by the script but ends `claude` early. The script plays the studio (heartbeat, one-time pass and Allow answer) and gives the session an `autoMode.hard_deny` rule through `--settings` so auto mode blocks its marked commands. It writes the fixture only when the log holds a `PermissionDenied`, a `StudioAnswer` and a wake-up for the session, and names what is missing otherwise.

The app tells you when the version changed. At a session's first `Stop`, it reads Claude Code's version from the session's transcript, the `.jsonl` file at the event's `transcript_path`, and opens no other file. It keeps each new version, with when it was first seen, in `claude-versions.txt` beside the event log. A version that differs from the last one kept shows a one-line notice at the top of the pane, a line in the Studio log, and a line in `weekly`. The first version kept has nothing to compare with, so it shows nothing.
