# Development

## The crates

- `plugin-agy/`: the studio's plugin for agy (#43). `hooks.json` runs `studio-hook` for agy's six events through an inline wrapper that always exits 0 with empty stdout; `studio-hook` writes an agy event only when `STUDIO_TERMINAL_ID` is set. `agy plugin install` copies the folder, so the app renders it with `studio-hook`'s path, compares it with `~/.gemini/config/plugins/studio/` at start and offers "Install it" when it is missing or stale.
- `plugin/`: the Claude Code plugin. On thirteen hook events, `SubagentStart` and `SubagentStop` among them, it runs `studio-hook`. On the `PreToolUse` of `AskUserQuestion` and `ExitPlanMode`, on every `PermissionRequest`, and on the `PermissionDenied` and `PreToolUse` of Bash, it also runs `studio-answer`, synchronously.
- `hook/`: `studio-hook`, which appends each hook payload as one line to the event log, and the log's path; and `studio-answer`, the answer hook (danielrispler/Falinks#477, danielrispler/Falinks#478): while the studio watches the asking session, it waits up to 120 seconds for an answer from the card and returns it: a question's `answers`, a plan's approval or rejection, a permission's allow or deny. It logs that answer as a `StudioAnswer` line, which clears "needs you" for a plan or a permission at once. Otherwise it returns at once with no decision and the terminal asks. On a Bash `PermissionDenied` it leaves a request in `blocked/<session>/` and waits up to 600 seconds, while the window shows life whatever session it shows, for Allow (`retry: true`) or Decline; Allow also leaves a 30-minute one-time pass in `passes/<session>/`, which the retry's `PreToolUse` claims and its `PermissionRequest` spends.
  - Its files and trust boundary are in `hook/src/answer.rs`.
- `core/`: the studio core, plain Rust whose only I/O is reading the sessions' transcripts (`src/transcript.rs`, `.jsonl` files only), and `scrub`, which turns event log lines into test fixtures. At start the app takes the state its last start saved, `studio-state.json` beside the log, and replays only the log from where that state stopped, then feeds it each new line live; a pruned log, a state of another format or one that does not read means a replay from the start. It keeps the step ledger (`ledger`), the checks (`checks`), each turn's files (`turn_files`) and the facts Ask shows (`ask`).
  - Only live lines request cards and notifications.
- `understanding/`: the understanding layer's I/O: the card writer interface (cards, turn summaries, Quizzes, goals and "Design so far"), the `claude -p` writer and a fake, the worktree fingerprint, the card store with the briefs, the turn summaries, the retests and the self-test's report (`self_test`), Claude Code's version kept beside the event log, and `weekly`, the command that prints the week's thinking and surprise rates, ratings by level and reason and flags on the key, then the drift: unrecognised wake-ups and version changes.
- `terminal-daemon/`: `studio-terminal-daemon`, the background process that owns the terminals, so they outlive the app (danielrispler/Falinks#322, danielrispler/Falinks#464). Its own crate and binary; the app links only its client library and runs the binary, so an app rebuild neither rebuilds nor restarts it. `serve` runs it on `~/Library/Application Support/dev.falinks.studio/terminal-daemon.sock`, one at a time; the protocol is in `src/lib.rs`.
  - Every terminal starts through `$SHELL -l`, so the profile sets `PATH` even when the studio was started from the Dock, and without `CLAUDE*` or terminal-identity variables. That shell is not interactive, so zsh reads `~/.zprofile` and `~/.zshenv` but not `~/.zshrc`. Set up every tool a session needs, such as `node` and `npm`, in one of the first two; nvm's installer writes its lines to `~/.zshrc`, so move them to `~/.zprofile` (#20). `attach <terminal>` connects any terminal app to one of its terminals; Ctrl-] detaches.
- `workbench/`: workbench git (danielrispler/Falinks#328, module 7): the picker's workspaces from `git worktree list --porcelain`, and the `claude` command a session's terminal runs.
- `src-tauri/`: the app's Rust shell, with the terminal daemon's client (`src/terminal.rs`). `ui/`: its TypeScript pane.

It leaves out the shell, which needs `dist/` from `npm run build`.

`npm test` (after `npm ci`) builds the UI with `tsc` and runs `terminal-daemon/tests/replay.test.mjs`: a terminal's bytes replayed into a headless xterm of another size, with the resize sent, match a fresh render at that size; and `ui/tests/`: the UI's pure functions on the `tsc` output in `dist/`, such as the width rule's layout, the terminal's key mapping (`keys`) and its file paths (`paths`), a check card's verdict and quiz state (`check_cards`), what "now" holds in each state and a folded turn's line (`rail`), the evidence line (`evidence`), a Quiz before and after a pick or "Show the rest anyway" (`quiz`), the banner's 14 and 15 minutes (`banner`), the top bar's survival order (`layout`), hover as a state machine on an injected clock (`hover`), and Ask and the diff pane (`ask`, `diff`), the agent logos and the rows that show them (`logos`), the text each layout cut holds in a title (`full-text`), Pull main's flow and its errors (`pull`), the usage glance and tiles (`usage`), the snap page and its fixtures (`snap`: the stub, the rail's and the recorded terminal's), and the README's limits and links (`readme`); opening a thing in place leaves every other node of the rail the same object, on the tests' small DOM (`dom.mjs`).

The window calls the shell only through `invoke` (`ui/dom.ts`), which takes a command of the `Commands` map in `ui/types.ts` and gives its reply that command's type. The snap fixtures (`scripts/snap/fixtures.ts`, `rail-fixtures.ts`) are typed against the map, and `scripts/snap/base.ts` answers every command whose reply the window reads, so `npm run build` (`tsc -p scripts/snap`) fails on a reply that lacks a field, and on a command `base.ts` does not answer. A fixture may leave a command out: each starts from `...base`.

`npm run snap:rail -- <folder>` renders the rail's states from fixtures in Chrome, which `npm run check` leaves out. `npm run snap:all` renders every fixture once and fails on the first that ends in `snap:fail` or an uncaught error in the page; CI runs it after `npm run check`. `npm run snap:readme` draws the README's four pictures into `docs/studio/assets/readme/` the same way. `scripts/snap/record-terminal.sh` records the terminal for the hero picture; it runs a nested `claude` on your subscription, so run it yourself, outside auto mode.

`npm run check` runs them all in order: `cargo fmt --all --check`, `npm run build`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo test --locked --workspace` (the shell included) and `npm run test:node`. CI runs `npm ci`, `npm run check` and `npm run snap:all` in `.github/workflows/studio.yml`, on macOS. It runs for each pull request, and for each push to `main` or to an `issue-*` branch. The engine's `checks.yml` and `ci-checks` skip the studio.

## Recorded logs

Two fixtures in `core/tests/fixtures/` are real event logs, scrubbed by `scrub` (`core/src/bin/scrub.rs`). Each event keeps its shape and loses its content: text becomes `…`, and lists and objects become empty, except for what stays. What stays: ids, event names, `cwd`, the permission mode, a session's start source and end reason, agent ids and types, the `description` of a spawn or a Bash command, `isolation`, the paths of the files a tool reads or writes, skill names, the types and statuses in tool results, background tasks without their commands, exit codes, numbers, flags and timings.

An MCP tool keeps no text. Transcript and output paths become `…`. A prompt keeps only the markup Claude Code adds, with its ids and statuses, so a wake-up stays one; any other tag becomes `<…>`. A last message that asks Daniel something becomes `…?`.

- `checkpoint-day.jsonl`: the events of 2026-10-30, the checkpoint day of danielrispler/Falinks#347. Some of its sessions were still open at midnight.
- `subagent-run.jsonl`: a scripted session in a temporary repository that spawns a worktree worker and a read-only helper in the background, then stops the helper.

Re-record the second when Claude Code's version changes. The script runs a nested `claude` on your subscription, so run it yourself, outside auto mode:

    core/tests/record-subagent-run.sh

Quit the studio app first: it would take the session as live and ask for cards. The script builds `studio-hook`, runs the session with this checkout's plugin, and scrubs the session's events from the event log into the fixture. Before you commit the new fixture, run `cargo test` and check that each text it keeps is a label, an id or a path.

The app tells you when the version changed. At a session's first `Stop`, it reads Claude Code's version from the session's transcript, the `.jsonl` file at the event's `transcript_path`, and opens no other file. It keeps each new version, with when it was first seen, in `claude-versions.txt` beside the event log. A version that differs from the last one kept shows a one-line notice at the top of the pane, one line on stderr, and a line in `weekly`. The first version kept has nothing to compare with, so it shows nothing.
