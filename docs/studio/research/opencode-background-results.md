# OpenCode's background-subagent results: states, delivery and ordering

Research for #779 (an OpenCode wake-up names its own subagent, and a failed subagent ends failed), 28 November 2026. Questions: which `state` values a `<background-result kind="subagent">` inbox item can carry, how `delivery: "steer"` reaches a busy or idle parent, and whether one wake-up can take several results.

Every claim is marked **verified** (read in the code, with its link) or **inferred** (put together from code that was read, but not seen in a test or a run), with a confidence.

## How this was read

- **Source.** `anomalyco/opencode` at tag `v2.4.2` (commit `fc31a48`, 25 Nov 2026), cloned shallow into a scratch folder and read with grep and sed; nothing was installed, built or run. Links below point at that commit.
- **v2.4.1** (tag `v2.4.1`, commit `6f05140`) was compared file by file. `execution.ts`, `execution/subagent-report.ts`, `run-coordinator.ts`, `bus.ts`, `session-event.ts`, `session-interrupt.ts`, `subagent-job.ts` and `session.ts` are identical. `subagent-completion.ts`, `inbox.ts`, `job.ts`, `runner/llm.ts` and `schema/session-inbox.ts` differ only by refactors: a helper pulled out, the inbox lock moved into the service, an import renamed, a doc string added. Nothing in this note differs between the two versions. Verified.
- **The captures.** `local-evidence/2026-11-27-issue-370-opencode-runs/oc-a/capture.jsonl` line 145, the shape quoted in #779. Every capture we have shows only `state="completed"`.

## 1. The `state` values

The subagent's report is built in [`SubagentCompletion.deliver`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/subagent-completion.ts#L66-L95). Its status is a job status, one of `"running"`, `"completed"`, `"error"`, `"cancelled"` ([`job.ts:41`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/job.ts#L41)); a `"running"` status sends nothing ([`subagent-completion.ts:73`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/subagent-completion.ts#L73)). Verified.

The child's execution outcome maps to a status in [`resolveBody`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/subagent-report.ts#L56-L73). Verified, high confidence:

- **Fails** (`session.execution.failed`): `"error"`, and the body is the error message ([`subagent-report.ts:62`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/subagent-report.ts#L62)). A test expects `state="error"` with the transport error's text ([`subagent-report.test.ts:378-380`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/test/subagent-report.test.ts#L378-L380)).
- **Interrupted** (`session.execution.interrupted`, reason `user`): `"cancelled"`, body `Subagent cancelled` ([`subagent-report.ts:63`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/subagent-report.ts#L63)). Tests expect `state="cancelled"` when the child is interrupted ([`subagent-report.test.ts:384-391`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/test/subagent-report.test.ts#L384-L391)), when its job is cancelled before it starts ([`subagent-report.test.ts:396-436`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/test/subagent-report.test.ts#L396-L436)), and when the child session is deleted mid-run ([`subagent-idle-e2e.test.ts:789-821`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/test/subagent-idle-e2e.test.ts#L789-L821)). There is no separate "aborted" or "interrupted" string.
- **Interrupted by a server shutdown**: no report at all. The shutdown branch publishes `session.execution.interrupted` with reason `shutdown`, keeps the job running for the next server start, and returns before any report is prepared ([`execution.ts:161-166`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution.ts#L161-L166)). Verified, high.
- **Succeeds**: `"completed"`, with the child's last assistant text as the body, or `Subagent completed without a text response.` ([`subagent-report.ts:65-71`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/subagent-report.ts#L65-L71)). A corrupt message row also turns into `"error"` (line 66). Verified.
- **Resume given up after a restart**: when a child was interrupted repeatedly and won't be resumed, the restart sweep reports `"error"` with `Execution was interrupted repeatedly and will not be resumed automatically.` ([`restart.ts:33-36`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/restart.ts#L33-L36), [`restart.ts:408-415`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/restart.ts#L408-L415)). Verified.
- **No timeout state.** The status set has no "timed out" value (`job.ts:41`), and the subagent tool, report and completion code contain no timeout (grep for `timeout`/`timed` in those three files). Verified, high.

**`state=` and `metadata.state` can differ.** The attribute in the text is `"running"` when the child completed but still has background work running (its own shells or subagents). `metadata.state` always keeps the job status, `"completed"` in that case ([`subagent-completion.ts:82-92`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/subagent-completion.ts#L82-L92)). A test expects `state="running"` in the text for such a child ([`subagent-report.test.ts:200`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/test/subagent-report.test.ts#L200)). So `metadata.state` is one of `completed`, `error`, `cancelled`; the attribute is one of those or `running`. Verified, high.

**One child can report many times.** The tool tells the model that it gets a `<background-result>` "each time the child goes idle, including after later work" ([`subagent.ts:53`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/tool/plugin/subagent.ts#L53)). A busy period without a background job still reports to the parent, under a fresh id ([`subagent-report.ts:169-180`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/subagent-report.ts#L169-L180)). Verified. So a `completed` item doesn't mean the child is finished for good, and a later item for the same child can follow.

**When the parent cancels a child.** There are three paths:

- **The `interrupt` tool.** It exists only with the `full_codemode` flag. It cancels the child's jobs, then interrupts the child and its descendants ([`session-interrupt.ts:28-35`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/tool/plugin/session-interrupt.ts#L28-L35)). Its comment says "Cancelled jobs send no completion notice" (line 26). But reading the report code, the child's interruption still reports: `cancelSession` drops the job entry ([`job.ts:597-615`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/job.ts#L597-L615)), so `prepareSubagentReport` returns mode `none`. A child that has a parent is reported anyway ([`subagent-report.ts:140-145`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/subagent-report.ts#L140-L145)), and `resolveBody` gives `"cancelled"` for any interruption, in either mode (line 63). Inferred, medium confidence: no test of the tool was found (`grep -rl session-interrupt packages/core/test` is empty).
- **The child's session is deleted.** It reports `"cancelled"`, per the e2e test above. Verified.
- **The user interrupts the parent.** This doesn't cancel its children. The parent's settlement cancels only the job whose id is the parent itself, its own job as a child ([`execution.ts:169`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution.ts#L169)). `Session.interrupt` interrupts only that session ([`session/session.ts:290-292`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/session.ts#L290-L292)). So the children run on and report later. Inferred, medium.

**Not only subagents wake the parent.** Shell, image, video and Code Mode jobs send their own `<background-result>` items. A shell item has `metadata.source: "shell"` ([`shell/result.ts:86-90`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/shell/result.ts#L86-L90)). They go through the same synthetic steer-and-wake path ([`synthetic.ts:30-47`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/synthetic.ts#L30-L47)), so a wake-up can come from a non-subagent job. Filter on `metadata.source === "subagent"`. Verified.

## 2. `delivery: "steer"` and when a wake-up follows

**Delivery values.** Only `"steer"` and `"queue"` exist. The schema's own description: "steer delivers before the agent's next model call, even mid-work. queue waits until the agent finishes its current work, then delivers one queued item at a time. Sending defaults to steer." ([`schema/session-inbox.ts:11-15`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/schema/src/session-inbox.ts#L11-L15)). Subagent reports are always admitted as `steer` ([`subagent-report.ts:94`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/subagent-report.ts#L94)). A pending item can be switched between the two (`session.inbox.delivery.changed`, [`inbox.ts:269-289`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/inbox.ts#L269-L289)). Verified, high.

**After admission the parent is always woken**, unless it is in a revert ([`subagent-report.ts:126-128`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/subagent-report.ts#L126-L128)). It is also not woken when the admission conflicted on its id (line 104-111) or the parent was deleted (lines 77-80, 114-124). Verified.

**Busy parent: no new execution.** `wake` on a session with an active execution only rings its doorbell (`pendingWake`); it does not start one ([`run-coordinator.ts:135-144`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/run-coordinator.ts#L135-L144)). The `started` hook, which publishes `session.execution.started`, runs once per busy period ([`run-coordinator.ts:96-99`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/run-coordinator.ts#L96-L99), [`execution.ts:139-152`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution.ts#L139-L152)). Inside the running drain, every step boundary promotes pending steers ([`llm.ts:197-210`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/runner/llm.ts#L197-L210)). When the model would end its turn, a pending steer keeps the drain going instead ([`llm.ts:101-106`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/runner/llm.ts#L101-L106), [`llm.ts:183-196`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/runner/llm.ts#L183-L196)). If the drain had already decided to end, the doorbell makes the same execution drain again ([`run-coordinator.ts:73-84`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/run-coordinator.ts#L73-L84)). So the result joins the running turn with no new `session.execution.started`. Verified, high.

**One edge.** If the wake lands after the parent's execution fiber has exited but while its settle hook still runs, `settle` starts a successor execution. That publishes a fresh `session.execution.started`, right after the parent's own terminal event ([`run-coordinator.ts:113-119`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/run-coordinator.ts#L113-L119)). Verified.

**Idle parent: always a new execution.** `wake` on an idle session calls `start`, which forks the execution and publishes `session.execution.started` before its first drain (`run-coordinator.ts:86-111`, `execution.ts:146`). The drain finds the pending steer and runs the model. Verified, high. So with the exceptions above (revert, conflict, deleted parent), an idle parent always gets a wake-up after a subagent's report.

**`queue` behaves differently.** A queued item is taken only at an idle boundary, one at a time (`inbox.ts:586-590`, below). A drain that was woken with scope `steer` stops before queued input ([`llm.ts:77-82`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/runner/llm.ts#L77-L82)). Verified. Subagent results never use it.

## 3. Several items per wake-up, and the order of events

**One execution can take several items.** A promotion with steers pending delivers all of them at once, up to the first control item (compaction or move) ([`inbox.ts:573-591`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/inbox.ts#L573-L591), [`inbox.ts:609-614`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/inbox.ts#L609-L614)). Wakes that arrive while the execution exists coalesce into its doorbell (`run-coordinator.ts:135-144`). Verified, high.

Two children finishing close together therefore give one `session.execution.started`. Their two items are delivered either in the same promotion (if both were admitted before the first step's promote) or the second at a later step of the same execution. Inferred from the code above, high confidence; no test of exactly two sibling reports was found. A plugin can't assume one inbox item per wake-up, nor that the item enqueued just before a `started` is the only one it takes.

**Order on the bus, for an idle parent.** Verified, high. The child's settle hook runs these steps in sequence on one fiber:

1. `publishTerminal` publishes the child's `session.execution.succeeded`, `.failed` or `.interrupted`. Its commit callback writes the report to the job outbox in the same transaction ([`execution.ts:168-170`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution.ts#L168-L170), [`execution.ts:211-222`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution.ts#L211-L222)).
2. `settlement.deliver` calls `inbox.admit`, which publishes the parent's `session.inbox.enqueued` ([`execution.ts:173-175`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution.ts#L173-L175), [`inbox.ts:205-210`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/inbox.ts#L205-L210)).
3. `wake(parent)` runs only after `admit` returns (`subagent-report.ts:81-128`).
4. The parent's new execution yields once, then publishes `session.execution.started` (`run-coordinator.ts:96-98`).
5. When the drain promotes the item, the parent's `session.inbox.delivered` follows.

Each `bus.publish` of a durable event commits, then notifies listeners and the live PubSub inline before it returns ([`bus.ts:470-478`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/bus.ts#L470-L478), [`bus.ts:495-508`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/bus.ts#L495-L508)). So steps 1 and 2 reach subscribers in that order, synchronously on the child's fiber. Steps 4 and 5 run on the parent's forked fiber. They are asynchronous, but can only start after step 3, so they follow.

Other events can fall between these steps. Examples are `job.updated` and other sessions' events, and events of the parent itself if it was busy. Inferred, medium. The plugin receives the stream through `bus.subscribe` ([`plugin/host.ts:275-283`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/plugin/host.ts#L275-L283)), a PubSub that keeps publish order. Inferred from the PubSub use, medium-high.

**What a restart replays.** A report already in the outbox, from a crash between steps 1 and 2, is replayed by the restart sweep with the same id ([`restart.ts:346-387`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/restart.ts#L346-L387), [`restart.ts:401-405`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/execution/restart.ts#L401-L405)). There the child's terminal event belongs to the previous server run. Verified.

## Events that mark an inbox item's fate

All four are durable and carry `sessionID` and `inboxID` ([`session-event.ts:208-242`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/schema/src/session-event.ts#L208-L242)). Verified:

- **`session.inbox.enqueued`** carries the `item`. It is published once per admission; a re-admission of the same id is reconciled without a new event ([`inbox.ts:198-204`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/inbox.ts#L198-L204)).
- **`session.inbox.delivered`** marks the item consumed into the transcript. It is published once per row at promotion ([`inbox.ts:541-571`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/inbox.ts#L541-L571)), and its projector deletes the pending row ([`inbox.ts:371-383`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/inbox.ts#L371-L383)). It fires inside the parent's running execution, after its `session.execution.started`. So pairing `inboxID` from `enqueued` with `delivered` ties an item to the execution that took it, including one delivered mid-turn without a new `started`. Inferred as a pairing method, high confidence on the event order.
- **`session.inbox.cancelled`** marks a pending item that was removed before delivery ([`inbox.ts:259-267`](https://github.com/anomalyco/opencode/blob/fc31a485317970bcf6be7b431a9830aaef875731/packages/core/src/session/inbox.ts#L259-L267)).
- **`session.inbox.delivery.changed`** marks a switch between steer and queue.
