# New session and the project: prior art

Research question: when a user starts a new session in a tool with several projects, which project does it land in, and how does the user change that? Three parts: (1) a per-project "+" on the sidebar group header, (2) what the global new-session key and button default to, (3) a project chooser inside the new-session dialog. 18 November 2026.

It does not repeat `multi-repo-workspaces.md`, `herdr.md` or `shell-polish.md`. It adds the new-session path they lack. `shell-polish.md` already covers herdr's "+" menu and the "one + per tab strip" rule; this note is about the project, not the kind of thing created.

Studio terms follow `docs/studio/CONTEXT.md`: "project" is a git repository the studio lists. Other tools' words (thread, workspace, space, group) appear only when describing that tool.

Five of them (Superset, Vibe Kanban, cmux, Workmux, herdr) were shallow-cloned into a scratch folder and read with grep. Nothing was built or run.
- Docs and changelogs fetched as HTML and stripped to text: Conductor, AgentsRoom, Cursor. Their source is closed, so these rows are weaker.
- "Unverified" marks a claim I could not trace to a primary source. A tool with no row for a question had nothing on it.
- Nothing here judges how a UI feels.
- Weak spots:
  - Conductor's docs list the shortcut `⌘N` but say nothing about which repository a new workspace lands in.
  - Cursor's docs name no per-repo "+" and no picker for the Agents Window.
  - Superset's repo `superset-sh/superset` now redirects on GitHub to `ParadevAI/Paradev` ("Codex App and Conductor alternative"). The code still imports `@superset/ui`, so I treat it as the same app, but I did not confirm that with a vendor page.
  - Line numbers are as of the files read on 18 November 2026 and will drift.

Patterns worth adopting:

1. **The "+" lives on the project's own header and shows on hover (also on keyboard focus).** Zed, T3 Code, Superset, cmux. Every tool whose sidebar is grouped by project and has such a button hides it until hover. None keeps it always visible.
2. **It starts the session in that project, with no project question.** Zed and T3 Code create a draft at once; Superset opens the form with the project already picked; cmux creates at once.
3. **Keyboard and touch still reach it.** T3 Code shows the button on focus and always on touch; Superset shows it on focus-within; Zed's tooltip carries the global `NewThread` key.
4. **A context menu repeats it.** T3 Code's folder right-click menu and cmux's group right-click menu both list "new" next to rename and pin.
5. **Tools without a project-grouped sidebar have no such button.** AgentsRoom, Vibe Kanban, Workmux, and Conductor (grouped by user sections) put creation elsewhere.

Patterns worth adopting:

1. **The global key follows what the user is looking at.** Zed (active project or selected group), Superset (viewed workspace's project), cmux (active group), herdr (focused terminal's folder), Workmux (project in view). Five tools do this.
2. **When nothing is selected, fall back to last used, not to the first.** Superset: last choice, then the only project. T3 Code: last used, then first in the saved order. Only T3 Code ends at "first", and only after the last-used step. Nobody opens with "first in the list".
3. **A chooser appears only when the choice is real.** T3 Code opens it for `mod+n` when two or more projects are open; with one project there is nothing to ask.
4. **Two keys, two meanings.** Superset: `⌘N` opens the form, `⌘⇧N` creates in the current project at once. T3 Code: `mod+n` may ask, `mod+shift+n` never asks. A fast key and a form key coexist.
5. **The key's name matches the tooltip.** Zed's header "+" tooltip shows the `NewThread` key.

Patterns worth adopting:

1. **The chooser is a searchable popover, dropdown or modal list.** Superset, T3 Code, Conductor, Vibe Kanban, Workmux. I found no tool with one chip per project, and none with a row of project buttons in the dialog.
2. **The chooser shows the resolved default, not a blank.** Superset's pill shows the handed-in project; Workmux starts the cursor on the current one. The user confirms or changes.
3. **Search is optional for short lists.** Conductor turns it on at five repositories.
4. **A way to add a missing project sits inside the chooser.** Conductor ("Add repository"), Vibe Kanban ("+ Create new project"), T3 Code (add-project mode).
5. **Many tools skip the chooser because the context already names the project.** Zed, herdr, cmux, AgentsRoom.
6. **No tool gives the chooser its own key.** Superset's registry has none; changing it is by pointer or by search.

## Implications for the studio

Today: one "+" and `⌘N` open a picker on the selected session's project, else the first project in the list.

**Question 1: a per-project "+".** Shared pattern: a button on the project's own header, hidden until hover or focus, that starts the session in that project (Zed, T3 Code, Superset, cmux). Daniel's hover "+" on each project header matches this. Option to copy: T3 Code's version. It shows on hover and on keyboard focus, always on touch, and starts the picker (or a draft) with that project fixed. Add the right-click entry, as T3 Code and cmux do. Zed's variant, a menu when a project has several open checkouts, matters only if the studio lists worktrees under one project.

**Question 2: the default of the global key and "+".** Shared pattern: follow the context, the viewed or focused project (Zed, Superset, cmux, herdr, Workmux). When there is no context, fall back to the last used project, and ask only if the user has two or more projects. The studio's present order is "selected session's project, else first". The first half matches Zed and Superset. The "else first" half matches only T3 Code's final fallback, and T3 Code tries last-used before it. So the studio should change the fallback, not the first step. Options to copy:
- Superset's order: viewed project, then last choice, then the only project, else empty and prompt.
- T3 Code's order: current, last used, first in saved order, with a chooser when two or more projects are open and no context decides.
- Two keys, as Superset and T3 Code have: the current key opens the picker; a second key creates in the current project at once.

**Question 3: the chooser in the picker.** Shared pattern: one control that shows the resolved project and opens a searchable list (Superset's pill, Conductor's selector, Vibe Kanban's dropdown, T3 Code's palette list, Workmux's modal). Daniel's project chips at the top of the picker do **not** match: no benchmark tool uses a row of chips. The nearest is Superset's single pill, which is one button, not one per project. Option to copy: Superset's pill or Conductor's selector, with the default pre-filled from Question 2's order, search shown only past about five projects, and an "add project" row at the bottom. If chips are kept anyway, there is no source to cite for them; that part would be a new design, not a copy.

Summary of the tentative idea: the hover "+" on the header is supported by four tools. The picker chips are supported by none. The stronger gap is the default (first project), which no benchmark tool uses as its primary rule.
