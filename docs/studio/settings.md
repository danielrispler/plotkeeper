# Settings files

`settings.json` and `keymap.json` sit in plotkeeper's data folder, `~/Library/Application Support/plotkeeper/`, in Zed's format: JSON with comments and trailing commas (danielrispler/Falinks#524). The page reads them when it opens, and `plotkeeper` sends them to every open page when either changes, within a moment of the save (it compares their text on each pass of its read loop, every 200 ms): an edit in your editor, or a save from another tab, takes effect with no reload, and the page's next save starts from the text the file holds. A page's save is still refused with "changed since the page read it: try again" when the file changed in the moment before it, and trying again then works. A file that does not parse is reported in the notice line, and the last good one stays in effect. Missing keys keep their defaults; a key of the wrong type is reported in the same line and keeps its default.

The page has no terminal (danielrispler/plotkeeper#326) and no project list to edit (a repository joins the saved project list on its first session, spec #380, #381), and one settings section (the explanations' switch aside, which the page writes from the `?` of an explained panel): the summary writer, in the Settings panel that the gear at the top of the page, or the palette's `studio::ShowSettings`, opens over the map (spec #320, #363; spec #380, #387). Every other key you edit in your editor. The keys it reads:

```jsonc
{
  "summaries": { "model": "haiku", "effort": "low", "on_open": false, "writer": "claude", "base_url": "http://localhost:11434/v1" }, // writer: "claude", "agy", "codex", "copilot", "cursor", "anthropic" (the API key) or "openai" (any OpenAI-compatible API); base_url: the OpenAI-compatible API's, set in Settings
  "briefBackfill": { "hours": 2 }, // at start, write PR briefs for ready PRs whose head moved within the hours, the newest first and at most 3; the older name `catchUp.hours` is still read when this key is absent
  "prBriefs": { "model": "opus", "effort": "low" }, // the model that writes a PR brief and a part catch-up and checks their claims; default: opus. effort: low (the default), medium, high, or "default" for claude's own, for the writer's and the retry's calls, never the claim check's, pre-flight's or a law draft's, which run at claude's own
  "checks": { "/path/to/app": ["make verify"] }, // per project folder, the commands that are checks; default: `cargo test` and the like, and `npm run check`. A background run allows only the project's own entry and has no default
  "setup": { "/path/to/app": "npm ci" },         // per project folder, one command a background run runs in its working folder before its agent starts; default: none
  "backgroundRuns": { "harness": "claude", "model": "sonnet" }, // the agent program of a background run (only "claude") and its model; default model: the CLI's own
  "explanations": true, // the dense panels' one-line explanations under each section (spec #520); default: true. The `?` beside the part sheet's ×, or the palette's `studio::ToggleExplanations`, writes it
  "tips": true, // a Wait tip at the foot of a running session's Intention box (#523, see the rail's doc); false turns them off; default: true
  "microWorlds": { "dshVisual": "~/work/dsh-skills/skills/dsh-visual/scripts" } // the folder holding dsh-visual's build.py and verify.mjs (with `npm install` run in it), which check a micro-world's page; unset: "Explore this" only copies a prompt
}
```

`checks`, `setup`, `backgroundRuns` and `microWorlds` are read by the server from the file each time a [background run](behaviour/background-runs.md) is asked for, so a saved change counts from the next run with no restart. `microWorlds.dshVisual` is also read each time the map is drawn, which decides whether Explore this starts a run ([Micro-worlds](behaviour/background-runs.md#micro-worlds)); a leading `~/` is your home folder.

## The writer section

The writer section, in the Settings panel over the map (the gear at the top of the page opens it), lists an Anthropic API key, when one is set, an OpenAI-compatible API, when its base URL or key is set, then the writers the login shell's `command -v` finds, Claude (`claude`), agy (`agy`) then Codex (`codex`); one that is not found, or a key that is not set, is listed but cannot be picked. Pick one, a model and, for Claude, an effort, and press Test: it makes one tiny call and shows its outcome, passed, or failed with why (not logged in, quota or rate limit, timeout, not installed, an empty or failed reply) and that writer's own fix. Nothing checks a login on its own, so opening the page spends nothing. A pass saves `summaries.writer`, `summaries.model` and `summaries.effort` in `settings.json` (an effort left at default removes its key); a failure saves nothing. The section opens on the writer in effect, or, while summaries are off, on the first writer found.

**The API key.** Under the list, paste an Anthropic API key and press Save key to add one, or a new one to replace it; Remove key removes it, after a dialog that names the Keychain key it deletes, with Cancel focused (#459). The key is kept in the macOS Keychain, in plotkeeper's own entry (service `plotkeeper`, account `anthropic-api-key`, which Keychain Access shows), and nowhere else: not in `settings.json`, not in the page and not in the log. plotkeeper never reads a key from another tool's config or from the environment, such as `ANTHROPIC_API_KEY`. The page learns only whether a key is set. With one set, the Anthropic API key writer comes first in the list and in the preset, and writes over HTTP with no CLI: the Messages API, with the model (`claude-haiku-5-5`, `claude-sonnet-5-5` or `claude-opus-5-5`; any full `claude-` id in `settings.json`, an alias such as `haiku` read as the first) and effort picked, schema-checked output when a call has a schema, and a 2-minute timeout. A refused key fails as having no working API key, with the fix to replace it; a quota or rate limit, a timeout and a server error fail as their kinds, which name only the HTTP status, never the error's body.

**The OpenAI-compatible API** (#367). Under the Anthropic key, its row takes a base URL and an optional key; Save keeps the base URL in `settings.json` as `summaries.base_url` and a pasted key in the Keychain, in plotkeeper's own entry (service `plotkeeper`, account `openai-api-key`), guarded as the Anthropic key is: never in `settings.json`, the page or the log. An empty base URL is OpenAI's own, `https://api.openai.com/v1`; an empty key field keeps the key set, and Remove clears both, after a dialog that names the base URL and the key, with Cancel focused (#459). With either set, the OpenAI-compatible API is listed and preset after the Anthropic key and before Claude. It writes over HTTP with no CLI: one chat completion at `<base URL>/chat/completions`, the key sent as `Authorization: Bearer` and no auth header without one (a local Ollama needs none). Its model is any id the endpoint serves, typed in the Model field, which offers `gpt-6-luna`, `gpt-5.6-luna` and `gpt-5.6-terra`; Claude's aliases, such as the default `haiku`, read as the first. Its effort is sent as `reasoning_effort` when one is picked, so pick default on an endpoint whose models take none. A call with a schema asks for schema-checked output (`response_format` with a strict JSON schema); an endpoint that answers 400 to that is asked once more without it, and the reply's object is read from its text and checked, as for Copilot. Its timeout is 2 minutes. A refused key fails as having no working API key; a quota or rate limit (402, 429), a timeout and any other error fail as their kinds, naming only the HTTP status, never the error's body; an endpoint that cannot be reached, such as Ollama not running, fails with the fix to check the base URL.

**The Test gate.** A user who arrives with no writer configured gets no summaries, Goals, Design so far, names or risk notes until a writer passes Test; the notice line says so. You count as configured when `settings.json` names `summaries.writer`, or when the data folder held `card-writer/`, which only an earlier start of plotkeeper (or the app before it) makes, at the first start of this version; that first look is kept in `writer-gate.json` in the data folder, and a passed Test sets it open for good. An existing setup therefore writes summaries after the upgrade with no Test.

PR briefs are written by `claude` whatever writer is picked. Without `claude`, no brief that needs the writer is written, and the writer section and the Map view's tray say briefs need Claude; a short brief, which code makes for a PR that changes the map but fogs nothing, is still stored, with its head's map check (spec #634).

The writer is the program that writes the turn summaries, the session's Goal and Design so far, and names (#327; PR briefs always use `claude -p`, whatever it says, with their own model setting above): `summaries.writer` is `"claude"` (the default, `claude -p`), `"agy"` (the Antigravity CLI, run with JSON schema output in a neutral empty folder of its own, with a 3-minute timeout that covers a logged-out `agy`'s 60-second wait), `"codex"` (`codex exec` on your ChatGPT login, in its own neutral empty folder, with a 3-minute timeout; its models are `gpt-6-luna`, `gpt-5.6-luna` and `gpt-5.6-terra`, and its effort is Codex's reasoning effort), `"copilot"` (`copilot -p`, the GitHub Copilot CLI; its models are `auto`, `claude-haiku-4.5`, `gpt-6-astra` and `gpt-5.3-codex`) or `"cursor"` (`agent -p`, the Cursor CLI; its models are `auto`, `claude-haiku-5-5-low` and `gpt-5.6-luna-low`), each in its own neutral empty folder with a 3-minute timeout and no effort setting. Neither Copilot nor Cursor takes a JSON schema, so the reply's object is read from its text and checked; their commands and replies were checked on real runs in wave 1's trial (#369), where only `auto` ran on the plans tried. What a writer reads is untrusted text, so each is locked out of tools as far as it allows: Claude runs with no tools; Codex has no such switch and runs in its read-only sandbox without your Codex config, so without your MCP servers; `agy` has neither and runs with its sandboxed terminal and no slash commands or skills (#364); Copilot runs with an allow-list naming no tool (`--available-tools=none`) and its built-in MCP servers off, and never stops to ask, and Cursor in its read-only ask mode (#365). Its `model` and `effort` are read by that program, so an `agy` model is one of `agy models`, such as `gemini-4-neon-low`; a `model` that is not in that list (the default `haiku`, with the writer moved to `agy`) is written with the first of the list, `gemini-4-neon-low`, and its `effort` is dropped. Codex, Copilot and Cursor likewise write a model they do not list with their first (Codex keeping the effort), while `claude` takes any model id. A writer that fails says "Summaries are off:" in the notice line, with why and its own fix, and reports why in one log line: not logged in, quota or rate limit, timeout, not installed, an empty reply, or another failure. Every writer sets `PLOTKEEPER_INTERNAL=1`, so the hook never records their runs.

An older file's `zoom`, `terminal`, `sounds`, `doctor`, `editor` and `repository` keys are ignored: the browser zooms the page, and there is no terminal, sound, Doctor or editor on it.

`keymap.json` is Zed's array of contexts: `Workspace` for the page and `List` for the session list while it has focus.

```json
[{ "context": "Workspace", "bindings": { "cmd-l": "studio::ToggleList", "escape": null } }]
```

The page's actions are listed, with their keys, in the palette (Cmd+Shift+P on macOS, Ctrl+Shift+Space on Linux; the defaults of both are in [the shortcuts table](behaviour/terminal.md)): `studio::ToggleList` (`[`: in a wide window the full list and its strip swap, below 1007 px the list opens over the map; not saved), `studio::ToggleRail` (`]`, the selected session's story closed and opened again), `studio::AskAbout` (Ask on the newest turn's Headline), `studio::OpenFullDiff` (the newest turn's whole diff), `studio::Dismiss` (Esc), `studio::ToggleFocus`, `studio::NextSession`, `studio::PreviousSession`, `studio::NextNeedsYou`, `studio::JumpToUnseen` (Cmd+Shift+U, the newest unseen session in any project), `studio::SelectNext`, `studio::SelectPrevious`, `["studio::Answer", "1"]` to `"4"`, `studio::ShowMap` (Cmd+Shift+M and Cmd+Shift+H, "back to the map": it closes the left panel; `studio::GoHome`, the old Home key's action, is read as it, so a `keymap.json` that still names it keeps working), `studio::FitMap` (`0`, the whole map in view), `studio::ShowHistory` (the ended sessions, searchable, in the left panel over the map; unbound), `studio::ShowSettings` (the Settings panel over the map, as the top bar's gear opens it; unbound), `studio::RefreshLanded` (looks up every task for Landed again), `studio::ToggleExplanations` (the explanations on or off, as the `?` beside the part sheet's × does; it writes `explanations` in `settings.json`; unbound) and `studio::Palette`.

Unlike Zed, binding an action to a new key unbinds its default key; `null` unbinds a key. A `Workspace` shortcut without Cmd (Ctrl on Linux), other than `studio::Dismiss`, leaves the key to the text box you are typing in; on Linux, so do Ctrl's text-editing keys, whatever they are bound to. On Linux the defaults are Ctrl's, so a `keymap.json` written there binds `ctrl-` keys, such as `"ctrl-l"`; a `cmd-` key there is the Super key.
